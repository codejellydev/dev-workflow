# dev-workflow

[English](README.en.md)

AI 코딩 도구로 실행하는 작업 절차를 프로젝트 밖에서 관리하는 저장소다.

규칙은 프로젝트에 둔다. 컨벤션 문서와 거기에 딸린 데이터다. 절차는 이 저장소에 둔다. 무엇을 모으고, 어떻게 보여주고, 결과를 어디에 기록하는지다. 그래서 도구를 바꿔도 프로젝트는 그대로이고, 프로젝트가 달라도 절차는 그대로다.

## 용어

| 용어 | 뜻 |
|---|---|
| 워크플로 | 한 종류의 작업을 처리하는 절차. 어떤 도구로 실행되는지 모른다 |
| 어댑터 | 한 도구에서 워크플로를 실행하게 하는 부분. 절차를 바꾸지 않는다 |
| 호스트 프로젝트 | 워크플로가 실행되는 프로젝트. 규칙과 데이터가 여기에 있다 |

## 워크플로

| 워크플로 | 하는 일 |
|---|---|
| [주석 검수](core/comment-review/README.md) | diff에서 새로 쓰거나 바뀐 주석을 전부 추출해 검사하고, 주석마다 대안과 추천을 제시해 사용자의 선택을 받는다 |

## 어댑터

| 도구 | 위치 | 진입점 |
|---|---|---|
| Claude Code | `claude/` | `/dev-workflow:comment-review` |

## 설치 (Claude Code)

```
/plugin marketplace add codejellydev/dev-workflow
/plugin install dev-workflow@dev-workflow --scope local
```

`--scope local`은 현재 프로젝트에서만 플러그인을 활성화한다. GitHub SSH 키가 없으면 먼저 `CLAUDE_CODE_PLUGIN_PREFER_HTTPS=1`을 설정한다.

아티팩트를 게시할 수 있는 세션이 필요하다. 주석 검수의 검수 페이지가 선택 내용을 아티팩트에 저장하기 때문이다.

개발할 때는 `claude --plugin-dir <이 저장소 경로>`로 실행하고, 수정한 뒤 `/reload-plugins`를 실행한다.

## 구조

| 위치 | 내용 |
|---|---|
| `core/<워크플로>/` | 절차, 프롬프트, 스크립트. 도구와 무관하다 |
| `claude/` | Claude Code 어댑터. 스킬, 에이전트, 훅, 검수 페이지 |
| `projects/<이름>/` | 한 프로젝트 전용 어댑터. 지금은 비어 있다 |

저장소 루트는 `dev-workflow` 플러그인을 배포하는 Claude Code 마켓플레이스이기도 하다.

## 확장

**워크플로를 추가할 때**

1. `core/<이름>/`을 만들고 절차를 `procedure.md`에 쓴다. 특정 도구의 이름이나 기능은 쓰지 않는다.
2. 판단 없이 처리할 수 있는 단계는 `scripts/`에 스크립트로 둔다.
3. 호스트 프로젝트가 준비할 파일과 한계를 `README.md`에 쓴다.
4. 어댑터마다 이 워크플로의 진입점을 추가한다.

**어댑터를 추가할 때**

1. 루트에 도구 이름으로 디렉터리를 만든다.
2. 워크플로마다 `procedure.md`를 그대로 따르는 진입점을 둔다.
3. 사용자에게 보여주고 선택을 받는 단계는 그 도구의 수단으로 구현한다.

규칙은 워크플로에도 어댑터에도 쓰지 않는다. 필요한 규칙은 호스트 프로젝트의 문서에서 읽는다. 현재의 예외는 각 워크플로의 한계에 적는다.
