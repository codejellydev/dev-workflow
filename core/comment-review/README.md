# 주석 검수

[English](README.en.md)

코드에 새로 쓰거나 바뀐 주석을 호스트 프로젝트의 컨벤션에 맞춰 검수하는 워크플로다.

세션이 길어지면 검수 품질이 떨어진다. 항목이 누락되고, 이미 정한 것을 다시 묻고, 기억에 의존해 "반영했다"고 보고한다. 아래 각 단계는 이 실패 지점을 하나씩 제거한다.

## 단계

1. **추출.** 스크립트가 diff에서 새로 쓰거나 바뀐 주석을 전부 나열한다. 기억으로 모으지 않는다.
2. **검사.** 스크립트가 기계적인 규칙을 적용하고, 판단이 필요 없는 것은 바로 수정한다.
3. **제안.** 새 컨텍스트에서 시작하는 검수자가 호스트 프로젝트의 컨벤션, 어휘, 지난 결정을 읽는다. 주석마다 현재 문장, 실질적인 대안 하나 이상, 삭제, 추천을 제시한다.
4. **검수.** 어댑터가 항목마다 수정 전 문장과 주변 코드를 보여준다. 사용자는 선택지를 고르거나 메모를 남긴다.
5. **적용.** 선택한 내용을 파일에 반영하고, 반영된 문장을 검색해 하나씩 확인한다.
6. **기록.** 라운드를 호스트 프로젝트의 결정 파일에 추가한다. 자동으로 수정한 수, 물은 수, 추천과 다르게 고른 수를 함께 남긴다.

목표는 "물은 수"가 줄어들고 "추천과 다르게 고른 수"가 낮게 유지되는 것이다.

## 구성

| 파일 | 역할 |
|---|---|
| `procedure.md` | 단계의 정의. 어댑터가 이대로 따른다 |
| `reviewer-prompt.md` | 3단계의 검수자에게 주는 지시 |
| `scripts/extract_comments.py` | 1단계. diff에서 주석을 추출한다 |
| `scripts/check_comments.py` | 2단계. 기계적인 규칙을 검사한다 |
| `scripts/record_decisions.py` | 6단계. 라운드를 기록한다 |
| `scripts/inject_rules.py` | 컨벤션의 주석 절을 출력한다. 컨텍스트가 압축된 뒤 규칙을 다시 넣는 데 쓴다 |

## 호스트 프로젝트가 준비할 것

| 파일 | 역할 |
|---|---|
| `Documents/Development/Conventions/CodingConvention.md` | 코딩 컨벤션. 주석 절은 `주석`이 들어간 `##` 제목이다 |
| `Documents/Development/Conventions/Comments/vocabulary.json` | 쓰는 말과 쓰지 않는 말 |
| `Documents/Development/Conventions/Comments/decisions.json` | 지난 검수 라운드 |

`vocabulary.json`은 항목의 목록이다. `pattern`이 있는 항목은 스크립트가 검사하고, 없는 항목은 검수자가 판단한다.

```json
{
  "entries": [
    { "use": "반환하다", "avoid": ["돌려주다"], "pattern": "돌려주|돌려줘|돌려준" },
    { "use": "수신하다", "avoid": ["받다"], "when": "원격 데이터를 가져올 때" }
  ]
}
```

`decisions.json`은 `{ "rounds": [] }`에서 시작한다. 기록 단계가 여기에 추가한다.

그 밖에 git과, `PATH`에서 `python`으로 실행되는 Python 3(3.14에서 확인)이 필요하다.

## 한계

- C#만 해석한다. XML summary, `//` 주석, `[Tooltip]` 문자열이 대상이다.
- `scripts/check_comments.py`는 일부 검사를 호스트 프로젝트에서 읽지 않고 직접 가지고 있다. summary는 마침표로 끝나고, `//` 주석과 Tooltip은 마침표 없이 끝난다. 메서드 summary는 합니다체 문장으로 시작하거나 `X Implementation.`이고, 그 외 summary는 명사형으로 시작한다. 이름이 `*Constants.cs`인 파일의 중첩 static class는 summary가 없어도 된다.
- 위 표의 경로는 스크립트의 기본값이다. 스크립트는 다른 경로를 인자로 받지만, 프로젝트마다 경로를 설정해두는 방법은 아직 없다.

규칙이 다른 프로젝트는 이 검사가 호스트 프로젝트 쪽 파일로 옮겨지기 전까지 스크립트를 직접 수정해야 한다.
